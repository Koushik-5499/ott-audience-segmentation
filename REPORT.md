# OTT Audience Segmentation & Personalization Report

> **IMPORTANT NOTICE:** As per the instructions and due to the lack of an officially provided `ott_users.csv`, this solution was developed and tested using **SYNTHETIC DATA**. All metrics, cluster profiles, and silhouette scores presented in this report and generated by the evaluator are derived from this synthetic dataset, not real viewer behavior.

## 1. Assumptions and Data Quality

### Synthetic Data Generation
A robust data generator was implemented (`data_generator/generate_dataset.py`) to mimic realistic OTT (Over-The-Top) viewer data. It introduces realistic noise, including:
- Duplicate records
- Negative watch times
- Outliers in `avg_session_mins` (e.g., sessions over 24 hours)
- Missing demographic data (`age` and `gender` which are intentionally ignored in modeling)
- Unseen/rare genres

### Data Assumptions
1. **Unsupervised Only**: As mandated, no labels (`user_id`, `age`, `gender`, or hypothetical subscription status) were used as features. The model purely identifies behavioral patterns.
2. **Missing Data**: Missing `sessions_per_week` and `weekend_ratio` are imputed with median values during training and inference.
3. **Genre Parsing**: Genres are semicolon-delimited. We assume a predefined vocabulary of genres built during training. Any unseen genres provided during inference are safely ignored to prevent breaking the pipeline.

## 2. Feature Engineering

The feature engineering pipeline is designed to be robust against outliers and highly skewed behavioral data:

1. **Log Transformation (`log1p`)**: `watch_time_hours` and `avg_session_mins` are highly right-skewed. Using `log1p` (log(1 + x)) dampens the effect of massive outliers (e.g., users leaving a stream running for days) and creates a more normal distribution for KMeans.
2. **Multi-hot Encoding for Genres**: The `top_genres` string is split and multi-hot encoded. We enforce a `min_df=0.01` (1% minimum document frequency) to ignore rare, noisy genres and reduce dimensionality.
3. **Genre Diversity Index**: A custom feature (`genre_diversity`) is engineered representing the total number of distinct genres a user watches. This strongly differentiates "explorers" from "niche/obsessive" viewers.
4. **Standardization**: All features are passed through `StandardScaler` to ensure KMeans distances are uniformly weighted across different units (hours vs. ratios).

## 3. K-Selection Methodology

Choosing the right number of segments ($K$) is fully automated in `trainer/main.py` using a data-driven approach:

1. **Sweep**: We evaluate $K \in [2, 8]$.
2. **Metrics Evaluated**:
   - **Silhouette Score**: Measures cluster cohesion and separation.
   - **Stability (Adjusted Rand Index)**: We run KMeans on two random 50% subsets of the data and measure agreement. High ARI means the clusters are structural, not artifacts of noise.
   - **Davies-Bouldin & Calinski-Harabasz**: Secondary structural metrics.
   - **Balance Threshold**: Any $K$ that produces a "micro-cluster" (containing less than 5% of the total population) is penalized or disqualified. We want actionable segments, not anomalies.
3. **Decision Logic**: The trainer selects the $K$ that maximizes the Silhouette score *among the candidates that pass the minimum balance threshold*.

## 4. Evaluation and Reliability

The system includes a dedicated `evaluator` service that comprehensively tests the API.

- **Idempotency**: Repeated requests yield identical segments.
- **Edge Cases**: Zero watch time, unseen genres, empty genres, and absurdly large inputs are handled gracefully with proper 422 validations or safe defaults.
- **Cold Start**: The system correctly returns a 503 Service Unavailable if queried before the model is fully trained and persisted to the shared volume.
- **Distance Metric**: The API returns `distance_to_centroid`, allowing downstream systems to measure "segment fit confidence" (e.g., treating borderline users differently).

## 5. Deployment and Operations

The solution is containerized in a strict multi-stage Docker Compose setup:
- **No Root Users**: All services drop privileges to a non-root user (`appuser`, UID 1000).
- **Atomic Persistence**: The `pipeline.pkl` and `metadata.json` are written atomically to a shared volume to prevent race conditions where the API attempts to load a partially written file.
- **Determinism**: Random seeds are fixed (`42`) across Python, NumPy, and scikit-learn to guarantee exact reproducibility of the synthetic dataset and the clustering boundaries.
